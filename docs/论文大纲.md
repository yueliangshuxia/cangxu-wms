### 摘要写作结构

1. **背景（1–2 句）**：中小仓储企业仍依赖人工经验，货位分配不合理导致拣货距离长、库存与设备数据分散。
2. **问题（1 句）**：如何在保证系统完整可用的前提下，把货位决策做得可解释、可复现。
3. **方法（3–4 句）**：设计并实现基于 Spring Boot + Vue 的 WMS；用 Apriori 挖掘订单关联，用 AHP 确定周转率、订单相关性、拣货距离、体积适配权重，用 TOPSIS 对候选库位排序并接入入库上架流程。
4. **实验（2 句）**：200 个 SKU、12,480 条仿真订单；与随机上架、ABC 分类对比；给出拣货距离、履行时间、库位利用率。
5. **结论（1 句）**：系统覆盖入库、出库、库存、盘点、退货、设备与审计，验证了方法的有效性，可作为中小仓储的参考实现。

### 第 4 章 基于 AHP-TOPSIS 的货位优化方法设计（约 4,000 字，算法核心章）

**4.1 问题描述与假设**

- 候选库位集合、商品集合、历史订单集合
- 假设：库位容量已知、出库口位置已知、历史出库明细可获取
- 目标：为待上架商品选择一个综合评价最高的空闲库位

**4.2 指标选取与量化**

- 4.2.1 周转率：历史出库数量，越大越好
- 4.2.2 订单相关性：与同库区已存商品的 Apriori 关联强度，越大越好
- 4.2.3 拣货距离：库区、巷道、列到出库口的距离，越小越好
- 4.2.4 体积适配：商品数量与库位容量的匹配度，越大越好

**4.3 订单关联分析**

- 事务化出库订单
- 频繁二项集与关联规则
- 将“商品—商品”关联聚合为“商品—库区”相关性得分
- 系统实现取当前库区已存 SKU 与待上架 SKU 的规则提升度之和

**4.4 AHP 权重计算**

- 判断矩阵：

| 指标 | 周转率 | 订单相关性 | 拣货距离 | 体积适配 |
|---|---:|---:|---:|---:|
| 周转率 | 1.00 | 1.26 | 1.55 | 2.00 |
| 订单相关性 | 1/1.26 | 1.00 | 1.23 | 1.59 |
| 拣货距离 | 1/1.55 | 1/1.23 | 1.00 | 1.29 |
| 体积适配 | 1/2.00 | 1/1.59 | 1/1.29 | 1.00 |

- 计算权重：0.340 / 0.270 / 0.220 / 0.170
- 一致性检验：CR = 0.000 < 0.1

**4.5 TOPSIS 排序**

- 指标正向化：距离为成本型，其余为效益型
- 向量归一化
- 加权决策矩阵
- 正/负理想解
- 贴近度排序，取前 5 个候选库位

**4.6 算法流程与复杂度**

- 输入：入库单、商品、空闲库位、历史出库明细
- 输出：候选库位及贴近度
- 流程图：读取候选 → 计算四项指标 → AHP 权重 → TOPSIS → 排序
- 复杂度：候选库位数 × 指标数；系统内候选库位限制为 8 个

- 基线：随机上架、ABC 分类
- 方法：AHP-TOPSIS
- 指标：平均拣货距离、平均履行时间、库位容积利用率

**6.5 实验结果与分析**

| 策略 | 平均拣货距离 (m/单) | 平均履行时间 (min/单) | 库位容积利用率 (%) |
|---|---:|---:|---:|
| 随机上架 | 186.2 | 3.8 | 72.2 |
| ABC 分类 | 162.5 | 3.4 | 72.1 |
| AHP-TOPSIS | 148.0 | 3.2 | 81.3 |

- 相对随机上架：距离 -20.5%，时间 -14.1%，利用率 +9.1 个百分点
- 相对 ABC 分类：距离约 -8.9%
- 解释：订单关联让关联商品同区，体积适配减少大库位浪费
- 局限：仿真数据、最近邻路线、未考虑拥堵与多人拣货

## 六、答辩 PPT 建议结构（10–12 页）

1. 封面：题目、姓名、专业、导师
2. 研究背景与痛点：货位靠经验、拣货距离长、数据分散
3. 研究目标与内容：一套 WMS + 一个可解释的货位决策
4. 系统总体架构：Vue → Spring Boot → MySQL；MQTT 虚拟设备
5. 核心业务闭环：入库推荐 → 出库波次 → 盘点/退货
6. AHP-TOPSIS 方法：四项指标、权重、TOPSIS 排序
7. 系统演示：登录、工作台、入库推荐、出库路线
8. 系统演示：设备监控、盘点、退货、审计
9. 实验结果：三种策略对比、20.5% / 9.1 个百分点
10. 测试与工程质量：14 项后端测试、Playwright、CSV 导出
11. 总结与展望
12. 致谢 / Q&A

**演示顺序建议**：入库推荐 → 出库路线 → 数据分析，不要从登录页开始逐个菜单点。

## 七、写作注意事项

1. **不要写硬件实物**：题目和正文都不承诺 ESP32、传感器、AGV 实物；统一写“虚拟设备 + MQTT 仿真验证”。
2. **实验数据必须标明仿真**：写清 200 SKU、12,480 条订单、生成规则和随机种子，不要伪装成企业真实数据。
3. **不要贴大段代码**：用“接口 + 流程图 + 关键代码片段 + 界面截图”的组合。
4. **公式要解释业务含义**：例如 TOPSIS 贴近度表示“候选库位离理想库位有多近”。
5. **图表要编号并被正文引用**：图 4-1、表 6-3 等。
6. **不要写“改进的 AHP-TOPSIS”**：本文是“融合订单关联与多指标评价”，没有修改算法本身，除非补了消融实验并有依据。
7. **查重**：第 2 章理论部分容易重复，用自己的话复述，公式和定义标注引用。
8. **数字一致性**：摘要、第 6 章、结论中的百分比必须来自同一份 `algorithm-comparison.json`。
