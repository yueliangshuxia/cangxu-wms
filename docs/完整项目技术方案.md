## 一、技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | Vue 3 + Vite + Vue Router + Pinia + Axios + ECharts | 复用当前 Demo 的设计 token 与页面结构 |
| 后端 | Java 21 + Spring Boot 4.0.8 + Spring Security + JWT | 企业级工程叙事，答辩认可度高 |
| 持久层 | MyBatis-Plus + MySQL 8.0 | 常规 CRUD + 自定义算法查询 |
| 缓存 | Redis 7（可选，当前未启用） | 当前直接查 MySQL/H2；Redis 仅作为后续热点缓存方案，未引入依赖 |
| 消息 | MQTT（EMQX 或 Mosquitto）+ Eclipse Paho | 设备接入层；无硬件时用模拟器发布 |
| 算法 | Java 实现 AHP / TOPSIS / Apriori；Python 做离线实验 | 系统内可调用，实验可复现 |
| 测试 | JUnit 5 + Postman/Newman + JMeter + Playwright | 功能、接口、性能、端到端 |
| 部署 | Maven Wrapper + Vite（当前）；Docker Compose + Nginx（后续，未在本机验证） | 当前直接运行；免安装版用 Spring Boot 内嵌前端 |

**为什么选 Spring Boot 而不是 Flask**：题目偏“智能仓储管理系统”，Spring Boot 的分层、鉴权、事务和设备接入更接近企业实现；答辩时“技术栈 + 架构”更容易讲。算法本身不依赖 Java 生态，AHP/TOPSIS/Apriori 都不难手写。

**前端是否用 Element Plus**：建议保留现在的自定义组件与 CSS，只在表单校验、日期选择等局部引入 Element Plus，避免整套 UI 被组件库风格带偏。如果开发时间紧，可以先用 Element Plus 快速搭后台，再逐步替换视觉。

## 五、虚拟 IoT 方案

### 5.1 MQTT Topic

| Topic | 方向 | Payload 示例 |
|---|---|---|
| `wms/sz01/sensor/{deviceId}/telemetry` | 设备 → 平台 | `{"ts":1760000000,"temp":22.6,"humidity":48}` |
| `wms/sz01/agv/{agvId}/state` | 设备 → 平台 | `{"ts":...,"battery":72,"state":"MOVING","task":"A-02-04"}` |
| `wms/sz01/rfid/{readerId}/scan` | 设备 → 平台 | `{"ts":...,"epc":"...","sku":"WH-1001","rssi":-52}` |
| `wms/sz01/alert/{deviceId}` | 设备 → 平台 | `{"level":"WARN","metric":"temp","value":28.4}` |
| `wms/sz01/cmd/{deviceId}` | 平台 → 设备 | `{"cmd":"SET_THRESHOLD","temp":26}` |

- QoS 1；AGV 状态使用 retained 消息，便于新订阅者立即拿到最新状态。
- 后端用 Paho 客户端订阅 `wms/sz01/#`，解析后写 `device_telemetry` / `alert` / `device.last_heartbeat`。
- 前端通过 WebSocket 或轮询获取实时值；第一版可用 5 秒轮询，后续换 STOMP/WebSocket。

### 5.2 模拟器设计

`simulator/`（Python 3.9 + paho-mqtt）：

- `devices.yaml`：设备清单（3 个网关、18 个温湿度/烟感、8 台 AGV、4 个 RFID 读写器）。
- 温湿度：按 24 小时正弦曲线 + 噪声；每 5 秒发布；可配置“越界”概率触发告警。
- AGV：状态机 `IDLE → MOVING → CHARGING`；电量按时间下降，低于 20% 自动回充。
- RFID：收到入库/出库任务时发布扫描事件；也可按固定频率模拟。
- 命令行：`python simulator.py --host localhost --port 1883 --scenario normal`。
- 场景：`normal` / `heatwave` / `agv-fault` / `rfid-burst`，用于答辩演示和测试。

**论文表述**：感知层采用“虚拟设备 + MQTT”验证接入链路；协议、topic、payload 与真实设备一致，硬件替换成本低。这样既贴物联网专业，又避免硬件调试风险。

## 六、算法实现

### 6.1 代码位置

```
backend/src/main/java/com/cangxu/wms/algorithm/
├── AhpWeightCalculator.java     # 判断矩阵、特征向量、CR
├── TopsisRanker.java            # 正向化、归一化、贴近度
├── AprioriAnalyzer.java         # 频繁项集、关联规则
└── SlotRecommendationService.java
```

- AHP：4×4 判断矩阵，特征向量用幂迭代或 `commons-math3`；输出权重和 CR。
- TOPSIS：指标正向化（距离为成本型）、归一化、加权、正负理想解、贴近度。
- Apriori：从 `outbound_order + outbound_item` 生成事务，挖掘频繁 2 项集，计算支持度/置信度/提升度；把商品关联度聚合到候选库位。
- 结果写 `slot_score`，并返回给前端抽屉展示；仓管员可人工调整，调整记录写审计日志。

### 6.2 实验

- Python 脚本 `experiments/`：读取导出的订单 CSV，跑随机 / ABC / AHP-TOPSIS（等权）/ AHP-TOPSIS（完整）四组。
- 指标：平均拣货距离、订单履行时间、库位利用率、拣货行走时间。
- 统计：10 次重复，均值 ± 标准差，配对 t 检验/Wilcoxon。
- 输出：CSV + matplotlib 图，直接放论文第 6 章。
- **注意**：系统内算法和实验脚本必须用同一套公式；建议先写 Java 版本，再用 Python 复现校验。

## 八、开发顺序（建议）

### Sprint 1：能登录、能看主数据（1–2 周）

1. 建 Spring Boot 工程、MySQL schema、统一响应、JWT。
2. 登录接口 + 角色权限。
3. 商品/供应商/客户 CRUD。

1. 入库单、收货、质检、上架。
2. 出库单、波次、拣货、复核。
3. 库存查询、流水、预警。
4. 前端对应页面接真实接口。

### Sprint 3：IoT 与扩展模块（2–3 周）

1. MQTT 接入 + 模拟器。
2. 设备监控、告警。
3. 盘点、退货、审计日志。
4. 库位平面图接真实库位表。

### Sprint 4：算法与实验（3–4 周）

1. AHP / TOPSIS / Apriori。
2. 上架推荐接口 + 前端抽屉。
3. 历史订单仿真、对比实验、消融与敏感性。

### Sprint 5：收尾（2 周 + 论文期）

1. JMeter 性能测试、Playwright 端到端。

3. 论文初稿、查重、答辩 PPT。

## 十、题目与方案的对应

无论最终选哪个题目，这套方案都能覆盖：

- 工程型题目：突出 Spring Boot + Vue + MySQL + 分层架构 + 测试。
- 物联网题目：突出 MQTT + 虚拟设备 + 设备监控 + 温区约束。
- 算法型题目：突出 AHP-TOPSIS + Apriori + 对比实验 + 上架推荐闭环。

因此**题目可以晚一点定**，先把 Sprint 1 的骨架搭起来不会浪费。
